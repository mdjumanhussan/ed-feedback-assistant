# 🏥 ED Feedback Assistant

A small **RAG (Retrieval-Augmented Generation)** app that answers questions about emergency department patient feedback.

Ask *"How do patients feel about waiting times?"* and it finds the most relevant comments, then writes a short answer that cites the comments it used.

> **Demo data only.** The app uses 200 synthetic (made-up) patient comments generated by `make_data.py`. No real patient data is used.

## How it works

1. **Retrieve:** the question is turned into an embedding (a list of 384 numbers that captures meaning). Chroma, a vector database, finds the 5 closest comments by cosine similarity.
2. **Augment:** those comments are numbered and passed to the model with strict rules.
3. **Generate:** Claude (Haiku 4.5) writes a 3 to 5 sentence answer and cites the comment numbers, so every claim can be checked.

## Safety: two layers

- **Score check:** if the best match scores below 0.35, the app says the feedback does not cover the topic and never calls the model.
- **Grounding rules:** the model must answer only from the comments, and say *"not enough information"* instead of guessing.

## What I learned from testing

- **Semantic search works on meaning, not words.** *"Was it hard to find a car space?"* returned parking comments, even though the word "parking" was never used. *"Staff were rude"* found *"the front desk staff seemed annoyed"*.
- **Retrieval always returns something.** With no food comments in the data, *"Was the food good?"* still returned 5 comments (about tea and a water station), with low scores around 0.3.
- **A score threshold alone is not enough.** *"Was the food good?"* scored 0.34 and was blocked, but *"Did patients enjoy the meals?"* scored 0.49 and got through. The grounding rules caught it, and the model correctly said there was not enough information.
- **Top-5 retrieval can skew the picture.** For waiting times, all 5 retrieved comments were negative, so the answer called feedback "entirely negative", even though positive waiting comments exist in the data. Retrieving more comments, or balancing by sentiment, would give a fairer summary.

## Tech stack

Python · Chroma (vector database, all-MiniLM-L6-v2 embeddings) · Claude API · Streamlit

## Files

| File | What it does |
|---|---|
| `make_data.py` | Generates 200 synthetic comments into `ed_feedback.csv` |
| `embed_demo.py` | Shows what embeddings are, and runs one similarity search |
| `build_db.py` | Stores all comments in a Chroma database |
| `search.py` | Command-line semantic search, with a sentiment filter |
| `ask.py` | The full RAG app in the terminal |
| `app.py` | The web version (Streamlit) |

## Run it yourself

```bash
pip install -r requirements.txt
# Set your Claude API key as the environment variable ANTHROPIC_API_KEY
python -m streamlit run app.py
```

The app builds the Chroma database from `ed_feedback.csv` on first run.
